# LINEとWebの登録導線案

2026年9月24日更新。以下は今後の実運用に向けた提案です。集客LPとLINEの既存フォームは従来のままです。新しい日程調整の流れは [操作デモ](COORDINATION_DEMO.md) に実装しました。

## 最新の方針：エントリーと日程調整を並行する

大阪・伊丹・神戸を初期の候補エリアとし、希望地域の順位は聞かず、先に治療希望者としてエントリーしてもらいます。先生と施設が対応できる日時を照合し、仮押さえした会場・日程を提示します。患者さんはその候補への参加希望を回答し、運営が開催条件を確認して確定します。行けない会場へ自動的に割り当てません。5人という開催目安と内部の人数調整は運営側で扱います。

入口は「LINEで日程の案内を受け取る」と「Webでエントリーする」の2つを、同じ台帳へ接続する案です。友だち追加だけではエントリーに数えず、本人の希望登録と連絡先の紐付けを確認します。日程未定でも登録でき、予定が合わなければ次回案内を待てます。

以下は当初の地域別集約案の記録です。「希望地域を先に入力する」方針は上記で更新します。LINEとWebの共通台帳・通知先の紐付けについての考え方は継続します。

## 推奨する形

スマートフォンではLINEを主な入口にし、LINEを使わずに登録したい方のためにWebフォームも用意します。両方から同じ登録項目・受付処理・地域別の管理台帳へつなぎます。どちらか一方から一度登録すればよい構成にします。

今回は地域ごとに希望を集め、医師・会場と調整して後日案内するモデルです。LINEで案内を受け取れる選択肢がこの運用に合う、という設計上の提案であり、登録率の向上を保証するものではありません。

| 入口 | ボタン案 | 登録後の案内 |
| --- | --- | --- |
| LINE（主な入口） | LINEで希望地域を登録 | 希望地域とLINEの通知先を紐付けたうえで、LINEで案内 |
| Web（もう一つの選択肢） | フォームで希望地域を登録 | 選択したメール・電話等で案内 |

スマートフォンの画面下部ではLINEのボタンを目立たせ、Webフォームの入口も読みやすく押せる大きさで併設します。PCではWeb登録とLINEへの案内を併記します。片方の登録後にもう片方の登録を必須にしません。

## 希望者として数える段階

LINEの友だち追加だけでは希望地域の登録完了として数えません。「友だち追加 → 希望地域等の入力 → 希望登録完了 → 開催調整 → 日程案内」とします。開催案内を受け取るための登録であり、予約確定と取り違えない名称にします。

初期入力は希望地域、年代、居住地域、名前、連絡方法など案内に必要な範囲を中心に整理します。治療経験・詳しい相談内容は任意または後日の確認とする案です。LINEで連絡先の紐付けができている場合は、メール・電話まで一律必須にする必要があるか見直します。

## 共通化と連絡先の紐付け

LINEのリッチメニューは外部Webページへリンクできます。そのため、サイトとLINEから同じWebフォームを利用する構成が可能です。[LINEヤフー公式マニュアル](https://www.lycbiz.com/jp/manual/OfficialAccountManager/rich-menus/)

通常のWebリンクを置くだけで、登録内容とLINEの通知先が自動的に結びつくわけではありません。本運用では、LIFF等を用いた認証・同意・登録との紐付け、通知処理を設計します。LIFFアプリは実行環境によりログイン処理が異なります。[LINE Developers公式ドキュメント](https://developers.line.biz/ja/docs/liff/developing-liff-apps/)

管理側では登録元、希望地域、連絡方法、連絡可否、日程案内の状態を共通の登録IDで管理します。重複は確認できた情報に基づいて処理し、氏名一致だけで別人をまとめないようにします。

## 現行デモとの関係

現行のLPフォームとLINE風画面は、どちらも操作体験用です。LINEへの接続、登録情報の送信・保存、地域人数の集計、日程通知は未実装です。この提案を採用する際に、共通フォーム化と本受付の実装を行います。
