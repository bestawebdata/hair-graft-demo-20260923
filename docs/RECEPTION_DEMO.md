# 受付・案内順の自動整理

2026年9月24日。日程照合に加え、受付担当が行う「誰へ何を案内するか」の整理を体験するデモです。

[8人の受付例を開く](https://bestawebdata.github.io/hair-graft-demo-20260923/coordination/?v=intake-1#reception)

このリンクは架空の8人のシナリオから開始します。通常の `/coordination/` は従来の4人の参加希望から始まり、「受付・案内順」→「8人の受付例を読み込む」で切り替えられます。読み込み時は、それまでのデモ操作をリセットする確認を表示します。

## 受付で聞くこと

日程ごとの参加可否に加え、本人が次の3項目を回答します。運営側も、本人から確認した回答を反映する操作ができます。

| 項目 | 選択肢 |
| --- | --- |
| 予約手続きへの希望 | 候補が合えば手続きに進める / 相談してから / まだ検討中 |
| 別日・別会場の提案 | 回答した候補に限る / 代案も受け取りたい / 変更前に相談したい |
| 今後の案内 | 案内を受け取る / 案内前に相談する / いったん止める |

「条件が合わなければ治療をやめそう」という人物評価や予測はしません。本人が回答した制約と意思を使います。「代案を受け取る」は自動的な予約変更への同意とは扱いません。案内を止めても登録を削除せず、治療キャンセルの確定処理もしません。

## 8人の例

| 登録者 | 回答の例 | 次の対応 |
| --- | --- | --- |
| 01・03 | この日程で参加可能、手続きへ進める、候補限定 | 案内候補の先頭に提案 |
| 02・04・05 | この日程で参加可能、手続きへ進める、代案も可 | 今回の残り枠へ提案 |
| 06 | 日程は合うが先に相談したい | 個別相談へ。確定人数には含めない |
| 07 | 日程・手続きの意思が未定 | 本人へ回答確認の案内 |
| 08 | 今回は都合が合わず、本人希望で案内停止 | 新しい案内の対象から外す |

提案順は、参加可能かつ手続きへ進める方の中で候補限定の方を先にし、同条件では登録順とする仮ルールです。年齢、居住地、連絡経路、医学的な状態や効果の見込みを順位に使いません。予約枠の収益最大化やキャンセル確率の予測、複数開催を横断した最適化は実装していません。

## 操作する

1. 上のリンクを開くと、今回の案内候補5人、相談・回答確認2人、案内停止1人が表示される。
2. 患者01の「本人回答を変更」から「相談してから決めたい」へ変えると、候補が4人となり開催確認ボタンが無効になる。
3. 「患者さんの画面」でも同じ希望が表示される。受付の希望を開き「候補が合えば手続きに進める」へ戻すと、候補が5人に戻る。
4. 「提案した対象者で開催確認へ」を押すと、提案順の5人がチェック済みになる。担当者が見直してから確定できる。
5. 「対応文を見る」では、開催前の案内、相談受付、未回答確認、次の候補の案内を、対象者の状況に合わせて作成する。実送信はない。

満員で今回の対象に入らなかった方は次回案内・空き枠待ちに回します。別の候補への参加回答がない方を人数に含めません。確定済みの方の変更は個別対応とし、他の開催へ二重に割り当てません。日程の空き時間が変わったり仮押さえが失効したりした場合は提案・文面作成を停止します。

## 本番化で決める運用

- 候補限定の方を先にするルールの承認と、柔軟な方が繰り返し後回しにならない待機期間・繰り上げ順のルール。デモの同条件内登録順を、サーバーの登録日時で扱う。
- 「お任せで決めてほしい」を受け付けるなら、対象会場・曜日・時間帯・案内期限などの許容範囲と本人同意を明示的に持つ。現在の「代案も受け取りたい」から、その同意を推定しない。
- 本人の回答日時・確認担当者・変更履歴・取り下げを保存する。日程への参加回答と受付全体への意思を別々に管理する。
- LINE等の回答リンク、未回答リマインド、相談担当への引継ぎ、回答期限、確定連絡の自動送信を接続する。案内停止を、すべての送信直前に再確認する。
- 人数到達時の開催確定、診察・説明、患者本人の予約確定を別の状態として扱う。臨床上の判断を受付の順位付けに代行させない。

このデモで自動化したのは、回答に基づく状態整理・案内候補の提案・文面作成・人数の再計算です。実際の予約登録、通知、相談対応、外部カレンダーの変更は行いません。ログイン・保存・通知の本番接続は [日程調整デモ](COORDINATION_DEMO.md) に記載しています。
