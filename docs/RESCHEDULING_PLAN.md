# 直前変更・開催延期・予約金の運用案

2026年9月24日。検討用の提案であり、決定済みの規約ではありません。現在のデモには決済・請求・返金・確定後の一括振替機能を追加していません。公表する料金条件や患者との契約内容は、実施医療機関・運営者で決定し、必要な専門家の確認を受けます。

## 先に決めること

先生の出張・会場・スタッフを確保する前に、開催するかを決める期限を設けます。仮押さえの期限、患者の予約確定期限、無料変更の期限、開催可否の判断期限を分けます。何日前とするかは、先生と病院が費用負担を確定する時点に合わせて決めます。

「最低5人」は開催を判断する時点の目安として扱い、一度開催を決めた後に1人が辞退しても残りの患者を自動的にキャンセルしない設計を推奨します。欠員時の継続判断、損失の負担、代わりの方への案内は運営と医療機関で決めます。

## 予約金を導入するなら

出張して実施する治療では、予約確定時に治療費の一部を予約金として預かる案は検討できます。希望登録の段階では無料とし、日時・会場・費用・必要な説明や診察・変更条件を確認して、本人が予約を希望する段階で扱います。実際の徴収時点は医療機関が確認します。

治療を受けた場合は治療費に充当します。金額を決める前に、直前の空き枠で回避できない費用、予約が埋め直せる割合、登録から予約へ進む割合、返金処理の負担を確認します。予約金の額とキャンセル料の額は別々に定め、一律に全額を返さない方式を前提にしません。

消費者契約法第9条では、同種の契約解除に伴う平均的な損害を超える違約金等について、超過部分が無効とされます。業界の相場だけで決めるものではありません。予約金から差し引くキャンセル料を含め、理由・時期ごとの条件と算定根拠を確認します。[消費者庁・第9条逐条解説](https://www.caa.go.jp/policies/policy/consumer_system/consumer_contract_act/annotations/assets/consumer_system_cms203_230915_16.pdf)

この治療・契約に特定商取引法の特定継続的役務提供等が該当するかは、本資料で判断していません。契約の内容・期間などに応じて別途確認する項目です。

## 変更理由を分ける

以下は推奨する運用方針であり、法律上の返金義務や責任の最終判断ではありません。

| 変更の事情 | 推奨する受付・対応 |
| --- | --- |
| 患者都合、変更期限より前 | Webで変更希望を受け付け、空いている日時を提案。新しい日時は本人の確認を経て決める。徴収済み予約金の振替・返金条件は事前に示す |
| 患者都合、直前・当日・無連絡 | 申出時刻を保存して担当者へ通知。欠員への案内と、事前に合意したキャンセル条件の確認を並行する。自動で予約金を没収しない |
| 患者の急な体調不良 | 早く相談できる導線を用意する。一般的な自己都合と同一の自動課金にせず、医療機関が判断する例外対応にする |
| 医師の体調・予定、病院の事情 | 開催側の変更として記録。本人の希望により振替または未提供の治療に対する予約金の全額返金を選べる方針を推奨。患者都合のキャンセル料を適用しない |
| 災害・交通遮断など | 開催継続の判断者を決め、延期・中止の連絡を優先。患者を自動的に無断欠席扱いしない。振替または未提供の治療に対する予約金の全額返金を選べる方針を推奨 |

交通費・宿泊費等の補償、医師・施設間の費用精算は予約金の返金と別の論点です。対象範囲・免責の可否を契約ごとに確認し、無制限の補償や一律の免責をこの段階では約束しません。

## 最初の本番運用から必要な機能

- 患者の変更申出を記録し、変更前後の日時・理由・申出時刻・対応担当者を残す。担当者が後で処理しても、申出日時を後ろにずらさない。
- 開催単位で「延期・中止」にする操作。旧日程の新規受付・予約リマインドを止め、該当患者だけを連絡対象にする。
- 対象者へ変更を案内し、「連絡未達・確認待ち・振替希望・返金希望・対応完了」を管理。配信済みと本人の確認済みを分け、直前の未確認者は電話等で対応する。
- 先生と施設の新しい日時を照合し、患者があらためて参加できる日時を回答。古い日程への回答を新しい日程へ流用しない。
- 空き枠の案内を希望した方に、日時と返答期限を提示して繰り上げを相談。自動的に来院確定として枠を埋めない。
- 徴収する場合は、予約金の受領・充当・返金待ち・返金完了を記録する。返金希望を選んだだけで返金済みにしない。

変更の受付と、変更先の確定は分けます。本人の取消申出を無視して予約を維持したり、相談中なのに別日へ確定したりしません。

## 段階的な導入

まず、明確な変更条件、予約前の意思確認、リマインド、欠員時の案内、延期時の連絡・再回答の管理を実装します。予約金を導入する場合は、少件数では医療機関の既存の支払手段と照合して始める余地がありますが、入金・返金台帳と責任者は必要です。

決済との自動連携、期限に応じた金額計算、自動返金、複数開催への再配置は、件数と運用ルールが固まってから拡張します。規模に応じて自動化の範囲は変えられますが、誰が延期を決め、誰に連絡し、誰が返金するかは初回開催前に決めます。
