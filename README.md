# 毛根グラフト再生治療 デモサイト

40〜60代男性を主な読者とした、スマートフォン優先の1ページ完結型サイトです。集客LPに加え、LINEの操作デモと、先生・医療機関・患者さんの日程を調整する運営デモを収録しています。集客LPは当初の地域別登録案、日程調整デモは最新の「先にエントリーし、候補日時に回答する」案を体験できます。

**説明用デモです。受付・予約・決済・メール送信は行いません。** 入力値はサーバー、ブラウザ保存領域、Cookieに保存しません。確認画面への引継ぎにメモリのみ使用し、完了時に氏名・連絡先等を消去します。

## 明日の打ち合わせで見る

- 公開URLと公開状態は [公開情報](docs/DELIVERY.md) を参照。
- オフラインでも `dist/index.html` をChrome、Safari等で開くと動きます。
- Macでは `デモを開く.command` をダブルクリックでも開けます。開けない場合は上のHTMLを直接開いてください。
- ソフトのインストール、ビルド、サーバー接続は不要です。

### LINE画面の操作デモ

[LINEの操作デモ](https://bestawebdata.github.io/hair-graft-demo-20260923/line/) を追加しました。ローカルでは `dist/line/index.html` を開けます。

リッチメニューの6項目を押すと、治療説明・医師紹介・症例・料金とリスク・地域選択・希望登録が開きます。「希望地域」→地域を選択→「デモ入力」→確認チェック→入力内容の確認→デモ完了、の順で体験できます。PCは左右2画面、スマートフォンはトークと案内画面を切り替えます。「最初から試す」で入力とトーク履歴を消去できます。

実際のLINEへの接続・友だち追加・送信は行いません。希望登録データの蓄積や予約確定もありません。詳細は [LINEデモの仕様](docs/LINE_DEMO.md) を参照。

### 日程調整・運営管理の操作デモ

[日程調整デモを開く](https://bestawebdata.github.io/hair-graft-demo-20260923/coordination/)。ローカルでは `dist/coordination/index.html` を開きます。

先生・医療機関の空き時間を自動照合し、仮押さえした日程へ患者さんが参加希望を回答する流れを体験できます。「患者画面を開く」から5人目の回答を入れると、運営が開催確定に進めます。予定変更、重複確保の防止、期限切れ、架空登録者の管理も実装しています。

今回の新方式は地域希望の順位を聞かず、会場と日程で回答してもらいます。すべて架空データで、本番カレンダー・通知・保存には未接続です。操作手順と本番化の設計は [日程調整デモの説明](docs/COORDINATION_DEMO.md) を参照してください。LP・LINEの既存フォームとの本接続は未実装です。

さらに [8人の受付・案内順のデモ](https://bestawebdata.github.io/hair-graft-demo-20260923/coordination/?v=intake-1#reception) を追加しました。本人の参加可否・手続きの意思・代案の希望から、今回の案内候補、個別相談、回答待ち、案内停止を自動で整理します。希望を変更すると候補と人数が再計算されます。操作方法と提案ルールは [受付デモの説明](docs/RECEPTION_DEMO.md) を参照してください。

### 3分で説明する手順

1. 最初の画面で、治療の案内と「地域から希望を集める」考え方を説明。
2. 「あなたの希望する地域から」で、登録 → 地域集約 → 医師・施設調整 → 日程案内を確認。
3. 医師紹介、30万円（仮・検討中）、リスク、未確定の開催場所を確認。
4. 希望地域をクリックしてフォームへ。「デモ用の内容を入力する」を押し、確認チェックを入れる。
5. 「入力内容を確認する」→「登録デモを完了する」で一連の体験を見せる。
6. 運営の説明が必要なら、場所の下の「地域連携の運営構想を見る」を開く。

## 収録内容

ファーストビュー、地域集約の仕組み、治療概要、医師紹介、相談例、治療の流れ、パンフレット掲載の比較写真6組、料金仮表示、リスクとダウンタイム、仮会場案内、地域選択、希望登録・問い合わせフォームを収録しています。

医療情報は既存の医師資料・施術同意書に基づきます。事業計画中の「ダウンタイムなし」など医師資料と矛盾する表現は採用していません。医師紹介資料から上田医師の人物写真・診療風景・学会発表の3点を抽出して掲載しています。診療写真は今回の毛根グラフト施術写真として扱っていません。2026年9月23日、ユーザーから医師監修のパンフレット掲載写真を使用してよい旨を確認し、比較写真6組を公開デモに反映しました。原資料の「術前・4か月後」と左右の対応を維持しています。病院の写真・電話・実予約リンクは流用していません。

2026年9月24日、LPとLINEデモを患者向けの原稿に統一しました。髪の改善への期待、上田医師の経歴、少量の採取・当日帰宅・翌日からの洗髪を分かりやすく紹介し、効果の個人差とリスクは併記しています。出典・編集上の確認事項は管理文書にまとめています。

「自分の組織」等の略記は「自分の皮膚組織」に統一しています。LINEとWebフォームの今後の導線案は [登録導線の提案](docs/REGISTRATION_FLOW.md) を参照してください。

### 症例を追加する場合

既存パンフレットの比較写真は `brochureGallery` で管理します。今回のユーザー確認に基づき公開しています。未提示の撮影条件や施術回数を確認済みに書き換えてはいません。

今後、新しく記録する症例は `docs/case-template.json` の形に沿って `cases` に追加します。現在は `cases: []` です。`status: approved`、本人の掲載同意、医師確認、同一撮影条件の確認、治療内容・回数、費用、リスク、画像と説明がそろわない新規記録は表示しません。条件フラグは承認ワークフローの代用ではなく、静的編集時の誤表示防止です。確認記録そのものや個人が特定できる情報は公開ファイルに入れないでください。

`observations` に時点を追加すると経過写真が増えます。時期は医師と調整して設定します。固定の治療結果や架空の経過は初期データに含めていません。

## Gitと公開

このディレクトリだけを新規Gitリポジトリとして分離しています。既存サイト・既存リポジトリ・Xサーバーには変更を加えていません。

ソースは `codex/hair-graft-demo` ブランチ、公開用ファイルは `gh-pages` ブランチです。`dist/` の中身だけを公開用ブランチへ反映します。公開元ファイルに秘密情報・原資料を含めないでください。

`node scripts/check.mjs` で構文・参照・デモ設定の基本確認を実行できます。`node scripts/publish-pages.mjs` はコミット済みソースの `dist` を `gh-pages` ブランチへ反映し、2ブランチをpushします。**外部への公開操作です。** 原稿の最終確認後に実行してください。

## 本受付への移行

このデモをそのまま本受付に切り替えることはできません。医療機関・担当医・料金・リスク等の最終確認と、個人情報の取扱い、同意、保存、アクセス制御、予約連携の実装が必要です。対象の確認項目はTODOにまとめています。デモの `noindex` は検索掲載を抑える指定であり、アクセス制限ではありません。
